## 1. LayerNorm rule — the detach

### 1a. The detach itself

The LayerNorm implementation lives in `utils.py`, class `LayerNormImpl`. The branch actually used
by this project is `mode == 'nowb'`:

`utils.py:81-89`
```python
        elif self.mode == 'nowb':
            mean = input.mean(dim=-1, keepdim=True)
            std = input.std(dim=-1, keepdim=True)
            if self.mean_detach:
                mean = mean.detach()
            if self.std_detach:
                std = std.detach()
            input_norm = (input - mean) / (std + self.eps)
            return input_norm
```

The flags are read from the args object in the constructor:

`utils.py:35-36`
```python
        self.mean_detach = args.mean_detach
        self.std_detach = args.std_detach
```

**Answer: YES, the mean and the std are separately detachable.** They are guarded by two
independent boolean flags (`self.mean_detach`, `self.std_detach`), each applied by its own `if`
statement to its own tensor. There is no code path that couples them.

### 1b. The normalizer is `(std + eps)`, NOT `sqrt(var + eps)`

The denominator is literally `(std + self.eps)` — `utils.py:88`. It is **not** `sqrt(var + eps)`.

**DEVIATION FLAG (code vs. canonical LayerNorm):** the canonical LayerNorm (and
`torch.nn.LayerNorm`) computes `(x - mean) / sqrt(var + eps)`. This code computes
`(x - mean) / (std + eps)`. These differ whenever `eps > 0`: `sqrt(var + eps) ≠ std + eps`. Here
`eps` is passed as `config.layer_norm_eps = 1e-12` (`SST/run_sst.py:52`, `IMDB/run_imdb.py:71`,
`IMDB/main.py:79`), so the numerical difference is tiny in practice — but the *functional form* is
different, and any formal claim that quotes this file must use `(std + eps)`.

**SECOND DEVIATION FLAG:** `input.std(dim=-1, keepdim=True)` is `torch.Tensor.std`, whose default
is `unbiased=True` (Bessel-corrected, divisor `n-1`). Canonical LayerNorm uses the *biased*
population variance (divisor `n`). The code does not pass `unbiased=False` anywhere. So the
normalizer is the sample standard deviation, not the population standard deviation.

**THIRD DEVIATION FLAG:** the mode name is `'nowb'` = "no weight, no bias". The `'nowb'` branch
returns `input_norm` directly — it never applies `self.weight` or `self.bias`. Compare the
neighbouring `'distillnorm'` branch, which does (`utils.py:100`: `input_norm = input_norm*self.weight + self.bias`).
So **the LayerNorm used throughout this project has no learnable affine transform in its forward
pass**, even though the parameters are still registered (`utils.py:41-43`) and therefore still
loaded from the checkpoint. Any formal model of "the LayerNorm in Ali et al.'s code" should omit
the γ/β affine term.

            return LayerNormImpl(args, normalized_shape, eps, elementwise_affine)

## 3. Linear-layer rule — `make_p_layer`, `pproc`, and gamma

### 3a. `make_p_layer` — this is ρ(w)

`xai_transformer.py:43-47`
```python
def make_p_layer(layer, gamma):
    player = copy.deepcopy(layer)
    player.weight = torch.nn.Parameter(layer.weight+gamma*layer.weight.clamp(min=0))
    player.bias   = torch.nn.Parameter(layer.bias +gamma*layer.bias.clamp(min=0))
    return player
```

**What is `rho(w)`?** There is no function literally named `rho` in the repository (verified: a
whole-word grep for `rho` across all `.py` files returns nothing). `make_p_layer` *is* the ρ
transform, expressed operationally:

- ρ(w) = `w + gamma * max(w, 0)`, i.e. ρ(w) = (1+γ)·w for w > 0 and ρ(w) = w for w ≤ 0.
- The **bias is transformed identically**: ρ(b) = `b + gamma * max(b, 0)`. This is worth noting —
  some LRP-γ formulations leave the bias untouched or drop it; here it is amplified in the same way.
- `copy.deepcopy(layer)` means `player` is a fresh module with fresh `Parameter`s; the modified
  weights are *not* tied to the original layer's parameters.

The three attention projections and the output dense layer each get a p-layer:

`xai_transformer.py:158-160`
```python
        pquery = make_p_layer(self.query, gamma)
        pkey = make_p_layer(self.key, gamma)
        pvalue = make_p_layer(self.value, gamma)
```

`xai_transformer.py:100-101` (in `BertSelfOutput.pforward`)
```python
        pdense =  make_p_layer(self.dense, gamma)
        hidden_states = pdense(hidden_states)                        
```

### 3b. `pproc` — the forward-value / backward-gradient split

`xai_transformer.py:147-151`
```python
    @staticmethod
    def pproc(layer,player,x):
        z = layer(x)
        zp = player(x)
        return zp * (z / zp).data
```

**Exactly what `zp * (z / zp).data` does.**

- `z = layer(x)` is the *true* layer output (weights `w`, bias `b`).
- `zp = player(x)` is the *modified* output (weights ρ(w), bias ρ(b)).
- `.data` strips the tensor from the autograd graph, making `(z / zp)` a **constant** `c` with
  `c = z / zp` evaluated numerically at the current input.
- **Forward value:** `zp * c = zp * (z/zp) = z`. The returned tensor is numerically *identical to
  the unmodified layer output* `z`. The forward pass of the network is unchanged by γ.
- **Backward gradient:** only `zp` carries a graph, so `∂(output)/∂x = c · ∂zp/∂x = (z/zp) · ρ(w)`.
  The backward pass therefore uses the γ-modified weights ρ(w), rescaled elementwise by the
  constant ratio `z/zp`.

**INFERENCE (standard LRP-γ reweighting identity):** this is the usual "gradient×input as LRP"
reformulation — a relevance `R_out` at the output is redistributed proportionally to
`x_i · ρ(w_ij) / Σ_i x_i ρ(w_ij)` once the gradient is multiplied by the input at the block
boundary (§4). Marked INFERENCE because the code contains no comment, docstring, or derivation
saying so.

**NO EPSILON STABILIZER.** `(z / zp)` has no `+ eps`, no `+ sign(zp)*eps`, no clamping. If any
element of `zp` is exactly zero the ratio is `inf`/`nan`. There is a commented-out NaN debug hook
nearby (`xai_transformer.py:184-185`: `#if torch.isnan(attention_scores).any():` /
`#    import pdb;pdb.set_trace()`), suggesting the authors encountered NaNs, but no stabilizer was
shipped. **Any formal claim that this implements "LRP-γ with ε-stabilization" is unsupported by
this code.**

## 4. Relevance readout — the backward loop

`xai_transformer.py:321-376` (inside `BertAttention.forward_and_explain`)
```python
        for i,block in enumerate(self.attention_layers):
            
            # [1, 12, 768] -> [1, 12, 768]
            attn_inputdata = attn_input.data
            attn_inputdata.requires_grad_(True) 
                        
        
            A['attn_input_{}_data'.format(i)] =attn_inputdata
            A['attn_input_{}'.format(i)] = attn_input
            
            
            gamma = 0. if gammas is None else gammas[i]
          #  print('using gamma', gamma)
            
            output, attention_probs = block(A['attn_input_{}_data'.format(i)], gamma=gamma, method=method)

            self.attention_probs[i] = attention_probs
            attn_input = output
            
                
        # (1, 12, 768) -> (1x768)

        outputdata = output.data
        outputdata.requires_grad_(True) 

        pooled = self.pooler(outputdata) #A['attn_output'] )

        # (1x768) -> (1,nclasses)
        pooleddata = pooled.data
        pooleddata.requires_grad_(True) 
        
        logits = self.classifier(pooleddata)
        
        A['logits'] = logits
        
        # Through clf layer
        Rout = A['logits'][:,cl]
        
        self.R0 = Rout.detach().cpu().numpy()
        
        Rout.backward()
        ((pooleddata.grad)*pooled).sum().backward()
                
        Rpool = ((outputdata.grad)*output)
                   
        R_ = Rpool         
        for i,block in list(enumerate(self.attention_layers))[::-1]:
            R_.sum().backward()
            
            R_grad = A['attn_input_{}_data'.format(i)].grad
            R_attn =  (R_grad)*A['attn_input_{}'.format(i)]
            if method == 'GAE':
                self.attention_gradients[i] = block.get_attn_gradients().squeeze()                 
            R_ = R_attn

        R = R_.sum(2).detach().cpu().numpy()
```

**CONFIRMED: relevance is computed as literally gradient × input at block boundaries.** The
pattern is explicit and repeated:

- `((pooleddata.grad)*pooled)` — `xai_transformer.py:362`
- `Rpool = ((outputdata.grad)*output)` — `xai_transformer.py:364`
- `R_attn = (R_grad)*A['attn_input_{}'.format(i)]` — `xai_transformer.py:371`

The mechanism: the graph is deliberately **severed** at every block boundary by `.data` +
`requires_grad_(True)` (`xai_transformer.py:324-325`, `343-344`, `349-350`). This creates a chain
of independent sub-graphs. Relevance is then propagated one segment at a time: the scalar
`R_.sum()` is backpropagated into the *previous* segment (`R_.sum().backward()`,
`xai_transformer.py:368`), the resulting `.grad` on the severed input is fetched, and multiplied by
the *attached* (graph-carrying) copy of that same tensor `A['attn_input_{i}']`.

Note the pairing at `xai_transformer.py:328-329`: `A['attn_input_{i}_data']` is the **detached**
copy fed to the block, `A['attn_input_{i}']` is the **attached** copy used as the multiplicand.
This is what makes `R_ = R_grad * attn_input` itself a differentiable expression, so that
`R_.sum().backward()` can push relevance one block further down.

- Final aggregation: `R = R_.sum(2)` — sum over the hidden dimension (axis 2), giving one scalar
  relevance per token. `xai_transformer.py:376`.
- The relevance seed is the **logit** of the target class, not a softmax probability:
  `Rout = A['logits'][:,cl]` (`xai_transformer.py:357`), and it is stored as `self.R0`
  (`xai_transformer.py:359`) — presumably for the conservation check `Σ_i R_i ≈ f`.
- Returned as `{'loss': ..., 'logits': ..., 'R': R}` (`xai_transformer.py:384`).

**No `.data` severing occurs *inside* a block.** Within one block, ordinary autograd runs through
`pproc`, the (possibly detached) softmax, and the (possibly detached) LayerNorm. So "gradient ×
input at block boundaries" plus "modified local gradients inside blocks" is the complete
description of the method as implemented.

| `detach_KQ_LNorm_Norm` | `True` | `True` | `False` | `LNargsDetachNotMean` | Softmax + LN **std only** detached; mean stays differentiable. Legend: `LRP (AH+LN)`. |

**NAMING TRAP — flag for downstream use.** The variant *reported in the paper's plots* as
`LRP (AH+LN)` is `detach_KQ_LNorm_Norm`, which detaches **only the std, not the mean**
(`config.detach_mean = False` → `LNargsDetachNotMean`). The variant that detaches *both*
(`detach_KQ_LNorm`) is built and is the fallback default in the dispatch (`SST/run_sst.py:158-159`)
but is **not** in the list of cases actually evaluated (`SST/run_sst.py:139-146`). The trailing
`_Norm` in `detach_KQ_LNorm_Norm` denotes "the norm *only*", i.e. *fewer* detaches than
`detach_KQ_LNorm`, not more. Do not read the longer name as the stronger ablation.

The case-to-model dispatch:

## 6. NEGATIVE FINDINGS — what is NOT in this repository

Reported honestly; each verified by inspection and/or repo-wide grep at commit
`d0613ddbb0978a71e8fae4e186b7fe192eee05e0`.

1. **No typeset equations from the paper.** No `.tex`, no `.bib`, no PDF. A repo-wide grep over
   `*.py` and `*.md` for `equation`, `\frac`, `theorem`, `proposition`, `lemma`, `bound` returns
   **zero** hits. The `README.md` is 20 lines and contains no math. The only mathematical notation
   anywhere is two matplotlib axis labels in `plot_utils.py:146-147`
   (`'$\sum_i R_i$'` and `'output $f$'`) and two plot titles in `SST/run_sst.py:270-271`
   (`'($y_0$-$y_p$)$^2$'`, `'logits$_k$'`).

2. **No conservation bound, no error analysis, no conservation *test*.** There is no code that
   computes a conservation residual, a bound, or an error term. `SST/run_sst.py` declares
   `res_conservation = {}` (line 138) and `C = []` (line 150) and stores
   `res_conservation[case] = C` (line 263) — but **`C` is never appended to anywhere in the file**,
   so the stored conservation results are always empty lists, and `res_conservation` is never
   pickled or plotted. `IMDB/run_imdb.py` has no conservation machinery at all.

3. **The conservation figure cannot be reproduced from this repo.** `plot_utils.py:122` defines
   `plot_conservation(conservation_dict, savefile)`, but its only caller,
   `paper_plots.ipynb` cell 7, loads a hard-coded absolute path on the authors' machine:
   ```python
   res = pickle.load(open('/home/oeberle/explainable_embeds/XNLP/experiments/26012022_sst_conservation/conservation.p', 'rb'))
   ```
   That file is not in the repository, and no script in the repository produces it. **The
   conservation experiment's generating code is absent.** `plot_conservation` scatters
   `Σ_i R_i` (y) against `f` (x) with an identity line (`plot_utils.py:135-144`) — that is the only
   evidence in the repo of how conservation was assessed, and it is a *visual* check, not a bound.

4. **No epsilon rule, no epsilon stabilizer, no gamma discussion.** There is no LRP-ε
   implementation and no ε in any denominator except the LayerNorm `eps` (§1b), which is a
   numerical-stability constant of the *forward* pass, not an LRP stabilizer. γ appears only as the
   bare numeric arguments in §3d; there is not one comment, docstring, or markdown line explaining
   how γ should be chosen, why SST uses 0.00 and IMDB uses 0.01, or what its effect is.

5. **No `rho` function, no LRP-rule abstraction, no docstrings on the method code.** `pproc`,
   `make_p_layer`, `forward_and_explain`, and `LayerNormImpl.forward` all have **zero docstrings**.
   The only docstrings in the repo are in `attribution.py`, and they credit *other* work
   (`attribution.py:113-115`, `181-183`: "Quantifying Attention Flow in Transformers (S Abnar and
   W Zuidema, ACL 2020)").

6. **The model is NOT a standard BERT and NOT a full transformer.** Material for any formal claim:
   - **No feed-forward / MLP sublayer.** Repo-wide grep for `gelu`, `intermediate`,
     `feed_forward`, `BertIntermediate`, `BertOutput` returns **zero** hits. The "block"
     (`AttentionBlock`, `xai_transformer.py:110-216`) is *attention → output dense → residual →
     LayerNorm*, full stop. A standard BERT layer's second sublayer and its second LayerNorm do not
     exist here. So the method as implemented never had to define a rule for the FFN's GELU.
   - **No `1/sqrt(d_k)` attention scaling** (§2).
   - **`attention_mask` is accepted but never applied** (§2).
   - **LayerNorm has no learnable affine** (§1b, third deviation flag).
   - **Only 3 blocks** (`self.n_blocks = 3`, `SST/run_sst.py:54`, `IMDB/run_imdb.py:73`), loaded
     from a custom checkpoint (`SST/sst2-3layer-model.pt`, `SST/run_sst.py:75`), with only the
     *embeddings* taken from HuggingFace `textattack/bert-base-uncased-SST-2`
     (`SST/run_sst.py:67-73`).

7. **Checkpoints are not in the repo.** `SST/sst2-3layer-model.pt` and
   `IMDB/best_model_state_dropout_0.860.bin` are Google Drive links in `README.md:8-9` and are
   absent from the clone; neither script can run as-is.

8. **Dead / unreachable code that could mislead.**
   - `BertAttention.__init__` creates `self.output = BertSelfOutput(config)`
     (`xai_transformer.py:230`), but `BertAttention.forward` / `forward_and_explain` never call it —
     the only `BertSelfOutput` actually used is the one owned by each `AttentionBlock`
     (`xai_transformer.py:118`).
   - `rename_params` is defined in both run scripts (`SST/run_sst.py:77-80`,
     `IMDB/run_imdb.py:99-102`) and never called.
   - `LayerNormImpl` modes `topk`, `adanorm`, `distillnorm`, `gradnorm` (`utils.py:57-109`) are
     never reachable — every args class in this project sets `lnv = 'nowb'`.
   - `paper_plots.ipynb` cells 3-4 reference `data_sets['imdb']` and cases `saliency`, `chefer`,
     `attention_flow_2` that neither run script produces, so the notebook as committed will
     `KeyError`. Cell 9 is empty; cells 2 and 6 are empty.

9. **AMBIGUITIES I did not resolve (flagged, not guessed).**
   - Whether the `pforward` / `pproc` asymmetry (§3c) is intentional. Unresolvable from the repo.
   - Whether the `(std + eps)` vs `sqrt(var + eps)` form (§1b) is intentional or inherited from the
     fairseq-derived `LayerNormImpl`. The Facebook copyright header (`utils.py:2-7`) suggests
     inherited, but that is not proof.
   - Whether the paper's reported SST-2 "LRP" numbers were in fact produced with γ = 0 as the
     committed script specifies (§3d), or with some other γ. The repo pins γ = 0.00 for SST-2; I
     cannot check this against the paper from local files.
   - Whether `unbiased=True` in `input.std(...)` (§1b) was deliberate.
